# Phase 1 Wave 0 screenshot-proof matrix

## Purpose
Define the minimum screenshot proof needed before later Phase 1 support-art requests are approved.

## Why Wave 0 screenshots are mandatory
Wave 0 locks classification, but later waves must prove missing roles against real additive screens. Without screenshots, requests drift into repaint/taste asks and violate preserve-first doctrine.

## Shared-family proof expectations
For each planned shared family, attach:
1. At least two target-screen references.
2. Screenshot slots `01-base`, `02-interaction`, `03-truth-states`, `04-high-fx`, `05-low-fx`, `06-reduced-motion` where applicable.
3. Missing-role statement linking to readable truth or consistency gap.
4. Confirmation that preserved scenic owners remain in-frame and dominant.

Family-specific proof notes:
- frame/plaque/ribbon family: show at least two screens where current primitives cannot carry labels cleanly.
- overlay/mask pack: prove legibility gains without suppressing DOM truth.
- FX atlas: prove quality-tier coherence and reduced-motion fallback.
- hero overlays: prove support gap still exists after earlier support families land.

## Unjustified request examples
- “The current portraits look old; replace them in Wave 1.”
- “Repaint world map to unify style.”
- “Replace forge backgrounds while adding frame atlas.”
- “Ship new icon set before support plaques.”
- “Use FX glow to hide dense unreadable truth rows.”

## Scope confirmation
This matrix defines proof requirements only. It does not generate screenshots or art in Wave 0.
