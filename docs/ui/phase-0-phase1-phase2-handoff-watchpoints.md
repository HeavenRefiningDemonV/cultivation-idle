# Phase 0 — Phase 1 / Phase 2 handoff watchpoints

## Purpose
This is not a design wishlist. It records only justified future follow-ups visible from Phase 0 evidence and audit outcomes.

## Phase 1 support-art asks justified now

### Shared frame/plaque/ribbon family
- **Role missing:** consistent cross-screen support framing for labels/headers/chips without local ad-hoc drift.
- **Why reuse is insufficient now:** current assets can carry many screens, but evidence notes recurring local wrapper variance and repeated owner-label harmonization work.
- **Reusable across screens:** yes (Status, World, Manual Pavilion, Forge, Bounties/Expeditions, Prestige).
- **Evidence basis:** `docs/ui/phase-0-p0-08-manual-pavilion-recovery.md`, `docs/ui/phase-0-p0-11-forge-recovery.md`, `docs/ui/phase-0-p0-12-bounties-expeditions-recovery.md`, `docs/ui/phase-0-p0-13-prestige-recovery.md`.

### Overlay / mask pack
- **Role missing:** reusable emphasis overlays that preserve base-owner art while improving legibility hierarchy.
- **Why reuse is insufficient now:** repeated per-screen tuning indicates a reusable support role, not a repaint requirement.
- **Reusable across screens:** yes (hero + module surfaces).
- **Evidence basis:** `docs/ui/phase-0-p0-05-cultivation-recovery.md`, `docs/ui/phase-0-p0-09-techniques-recovery.md`, `docs/ui/phase-0-p0-13-prestige-recovery.md`.

### World/building label plaques
- **Role missing:** consistent diegetic map/building labels that avoid generic-shell fallback.
- **Why reuse is insufficient now:** World/support-board notes repeatedly call for clearer local label grounding.
- **Reusable across screens:** yes (World + routed building panels).
- **Evidence basis:** `docs/ui/phase-0-p0-07-world-recovery.md`, `docs/ui/phase-0-p0-12-bounties-expeditions-recovery.md`.

### Shared FX atlas (restrained)
- **Role missing:** reusable low-noise FX accents that stay coherent in high/low/reduced tiers.
- **Why reuse is insufficient now:** quality-tier consistency is repeatedly audited as required evidence, suggesting shared support-role value.
- **Reusable across screens:** yes (hero and ritual surfaces first).
- **Evidence basis:** `docs/ui/section-a-cutover-gate.md`, `docs/ui/section-a-screenshot-approval-workflow.md`, phase-0 packet reports noting mode-evidence requirements.

### Later-wave hero overlays
- **Role missing:** optional hero-only support overlays to reinforce existing owners without replacing them.
- **Why reuse is insufficient now:** only as optional follow-up once exact-screen gate proof is complete.
- **Reusable across screens:** partially (Cultivation, Prestige).
- **Evidence basis:** `docs/ui/phase-0-p0-05-cultivation-recovery.md`, `docs/ui/phase-0-p0-13-prestige-recovery.md`.

## Phase 1 asks that are NOT justified yet
- Whole new scenic map repaint.
- Replacement portrait families for Life Start/Cultivation.
- Replacement forgewide room paintings.
- Replacement bookshelf/spine art families.

These are overreach/repaint asks not justified by current Phase 0 evidence.

## Phase 2 shell watchpoints
- Preserve local screen owner precedence while harmonizing shared shell primitives.
- Keep routed modal shells (World-building, ritual family) non-dominant relative to active child screens.
- Maintain no-layout-shift guarantees when consolidating shared state controls/chips/badges.
- Preserve truth-in-DOM and avoid hover-only critical explanations during shell continuation.

## Not blockers
Items in this file are watchpoints, not unresolved Phase 0 breakage. They do not legalize cleanup and do not override exact-screen cutover requirements.

## Scope confirmation
This file is a handoff note only. It is not an implementation pass and not an art-request execution queue.
