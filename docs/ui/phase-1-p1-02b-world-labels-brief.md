# P1-02B — Dedicated World Labels / Building Plaques / City-Arrival Identity Brief

## 1) Packet purpose and scope

P1-02B defines the dedicated world-label / building-plaque / city-arrival identity family for World-facing contexts.

It is a sibling family to P1-02A (shared plaque/ribbon/title-plate). It does not replace P1-02A.

This family exists to solve the World Hub diegetic-label problem while preserving map ownership.

## 2) Why now

The World Hub requires a world-specific label system because generic shared plaques are not sufficient for map-attached identity and building context.

This packet comes before live World integration so later implementation can consume one consistent world-label family rather than ad hoc floating tags.

## 3) Doctrine inheritance

- preserve-first
- enhance-first
- additive only
- no future-art excuse
- no cutover without approval
- world map remains the base plane

## 4) Family boundary and exclusions

### In scope

- building label plaques
- selected-building emphasis plates
- district/area label plaques
- current-city identity plates
- city-arrival world banners
- world-only route-hint/breadcrumb plaques

### Out of scope

- generic shared plaque/ribbon/title family (P1-02A)
- state underlays/stamps/recommendation swashes (later state family)
- Gate/Forge/Apothecary support kits
- bounty-note and expedition route-slip local families
- live integration and scenic replacement

Ownership boundaries:

- P1-02A owns generic shared header/title roles.
- P1-02B owns world-specific diegetic labels.
- State-family packet owns stamps/swashes/underlays.

## 5) Continuity with shared shell and P1-02A

Shared continuity requirements:

- same parchment/ink material language
- same restrained sacred ornament discipline
- compatible value hierarchy with frame/plaque siblings

Hard constraints:

- must not act like floating software tags
- must not act like generic headers
- must not act like state ribbons
- must not act like tavern signs/hanging boards

## 6) Canonical role inventory

### A) Building label plaque

- **Role statement:** Default diegetic name plate for individual world buildings.
- **Intended screen examples:** World map building hotspots.
- **Hierarchy level:** Low-to-medium.
- **Intended emotional weight:** Quiet structural identity.
- **Prohibited usage:** Generic screen headers, state badges, non-world usage.
- **Text-safe zone:** 10/18/10/18 px.
- **Likely aspect ratio:** 2.8:1 to 4.5:1.
- **Stretch mode:** Semi-stretch.
- **Code tint:** Yes.
- **Pairs with shared plaque assets:** Optional; mainly pairs with light world support headers.
- **Ornament budget:** Low.
- **Center vs endcap behavior:** Calm center band, restrained ends.
- **Diegetic attachment:** Anchored to building position, never free-floating.

### B) Selected-building emphasis plate

- **Role statement:** Elevated variant for active/selected building focus.
- **Intended screen examples:** World selected/active hotspot.
- **Hierarchy level:** Medium.
- **Intended emotional weight:** Noticeably stronger than default building labels.
- **Prohibited usage:** State stamp replacement, non-selected defaults.
- **Text-safe zone:** 10/20/10/20 px.
- **Likely aspect ratio:** 3.0:1 to 4.8:1.
- **Stretch mode:** Semi-stretch with protected endcaps.
- **Code tint:** Yes.
- **Pairs with shared plaque assets:** Pairs with P1-02A shared hierarchy elements only as secondary context.
- **Ornament budget:** Low-to-moderate.
- **Center vs endcap behavior:** Endcaps can intensify slightly; center remains text-first.
- **Diegetic attachment:** Anchored to selected building; may rise one hierarchy step, still map-attached.

### C) District / area label plaque

- **Role statement:** Broader region identity marker for grouped map areas.
- **Intended screen examples:** World district clusters/area grouping callouts.
- **Hierarchy level:** Medium.
- **Intended emotional weight:** Broader context, calmer than arrival identity.
- **Prohibited usage:** Per-building default labels, city-arrival replacement.
- **Text-safe zone:** 12/22/12/22 px.
- **Likely aspect ratio:** 4.0:1 to 6.0:1.
- **Stretch mode:** Width variants (M/L) or controlled semi-stretch.
- **Code tint:** Yes.
- **Pairs with shared plaque assets:** Only for secondary hierarchy handoff, not generic header substitution.
- **Ornament budget:** Low-to-moderate.
- **Center vs endcap behavior:** Clear center text band; subtle area-specific endcaps.
- **Diegetic attachment:** Anchored to district area, not floating detached chips.

### D) Current-city identity plate

- **Role statement:** Persistent current-city identity marker in world-facing shell context.
- **Intended screen examples:** World top shell or world inspector city context.
- **Hierarchy level:** Medium-high.
- **Intended emotional weight:** Anchoring city identity below arrival banner weight.
- **Prohibited usage:** Generic breadcrumb for non-world screens.
- **Text-safe zone:** 12/24/12/24 px.
- **Likely aspect ratio:** 4.0:1 to 6.5:1.
- **Stretch mode:** Semi-stretch with protected ends.
- **Code tint:** Yes.
- **Pairs with shared plaque assets:** Compatible with P1-02A breadcrumb/title strips but world-specific variant remains distinct.
- **Ornament budget:** Moderate-low.
- **Center vs endcap behavior:** Center quiet; identity details remain legible.
- **Diegetic attachment:** Lives in world shell/inspector as world-specific identity, not generic app nav.

### E) City-arrival world banner

- **Role statement:** Heaviest world identity banner for city-arrival moments.
- **Intended screen examples:** World arrival transitions and first-entry context.
- **Hierarchy level:** High (heaviest in this family).
- **Intended emotional weight:** Ceremonial arrival emphasis.
- **Prohibited usage:** Persistent default building label replacement.
- **Text-safe zone:** 14/30/14/30 px.
- **Likely aspect ratio:** 5.0:1 to 8.0:1.
- **Stretch mode:** Semi-stretch with protected ornate ends.
- **Code tint:** Yes, restrained.
- **Pairs with shared plaque assets:** May align with P1-02A city-arrival siblings; world variant remains dedicated to world contexts.
- **Ornament budget:** Moderate-high at ends only.
- **Center vs endcap behavior:** Endcaps carry emphasis; center remains text-safe.
- **Diegetic attachment:** World-arrival context only, anchored to map/city identity.

### F) Route-hint / breadcrumb plaque (World-only)

- **Role statement:** Small world route-hint context strip for destination orientation.
- **Intended screen examples:** World quick-route hints near module routing context.
- **Hierarchy level:** Lowest.
- **Intended emotional weight:** Quiet supportive guidance.
- **Prohibited usage:** Generic breadcrumb system outside world contexts.
- **Text-safe zone:** 8/14/8/14 px.
- **Likely aspect ratio:** 3.5:1 to 5.5:1.
- **Stretch mode:** Nine-slice or S/M variants.
- **Code tint:** Yes.
- **Pairs with shared plaque assets:** May pair with quiet shared breadcrumb surfaces but remains world-only.
- **Ornament budget:** Very low.
- **Center vs endcap behavior:** Minimal ends; center strictly quiet and readable.
- **Diegetic attachment:** Positioned as world-facing hint tied to route context, not global nav tag.

## 7) Family-wide style laws

- xianxia parchment-and-ink language
- diegetic map attachment
- quiet sacred ornament
- no tavern-sign fantasy language
- no floating browser-tag behavior
- no thick western metal signboards
- no giant center emblem
- no neon/sci-fi linework
- no decorative clutter that harms map readability

## 8) Material / hierarchy rules

Hierarchy order:

1. city-arrival world banner (heaviest)
2. current-city identity plate
3. selected-building emphasis plate
4. district/area label plaque
5. building label plaque
6. route-hint plaque (quietest)

Rules:

- city-arrival banner is heaviest.
- current-city identity is below arrival.
- selected-building emphasis is stronger than ordinary building labels.
- district labels are broader but not louder than arrival identity.
- route hints are quietest.

## 9) Text-safe zone and padding rules

Role-class text behavior:

- building/selected labels: one-line default, optional two-line overflow for long names.
- district/current-city/arrival: one-line preferred, controlled two-line fallback.
- route hints: one-line only where possible.

Minimum safe insets (t/r/b/l px):

- building label: `10/18/10/18`
- selected-building: `10/20/10/20`
- district label: `12/22/12/22`
- current-city identity: `12/24/12/24`
- city-arrival banner: `14/30/14/30`
- route-hint: `8/14/8/14`

Additional rules:

- ornament zones are protected;
- center field remains quiet;
- optional chips in code must sit outside text-safe center where possible;
- long names should expand via width variant/stretch before aggressive font shrink.

## 10) Placement / diegetic rules

- Labels should appear attached to buildings or world zones.
- Labels must not float as generic software tags.
- Selected-building emphasis may lift hierarchy but remains map-attached.
- Current-city identity may live in world shell/inspector and remain world-specific.
- Route-hint plaques are world-facing supports only; not global breadcrumbs.

## 11) Stretch / size-variant rules

- **Fixed-width-first roles:** short route hints, selected compact variants.
- **Semi-stretch roles:** building labels, selected-building labels, current-city identity, arrival banner.
- **S/M/L variant roles:** district labels and route-hint families.
- **Not safe for aggressive stretch:** arrival ornate ends and dense district ornaments.

## 13) World-screen usage matrix

| Role | World use case | Why this role belongs | Why generic shared plaques are insufficient |
| --- | --- | --- | --- |
| Building label plaque | Default building naming on city map | Provides diegetic, repeatable building identity | Generic header plaques read as floating UI, not map-attached labels. |
| Selected-building emphasis plate | Hovered/selected building focus | Raises hierarchy for active target clarity | Shared headers do not encode building-attached emphasis safely. |
| District/area label plaque | Grouped district zoning | Provides broader spatial grouping context | Generic strips lack world-zone attachment semantics. |
| Current-city identity plate | Persistent current-city context | Anchors city identity in world shell/inspector | Generic breadcrumb strips risk app-nav look outside world context. |
| City-arrival world banner | Arrival identity moment | Conveys ceremonial arrival context | Generic titles are too global and not world-state-specific. |
| Route-hint plaque | Quick route guidance in world flow | Provides quiet world-only route context | Generic breadcrumbs become non-diegetic software tags here. |
