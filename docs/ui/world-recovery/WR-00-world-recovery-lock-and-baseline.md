# WR-00 — World recovery lock and failure baseline

## A. Packet role

WR-00 is a governance/baseline packet only. It locks recovery rules, records the current failed World composition as the branch baseline, and aligns evidence/signoff language so WR-01 through WR-09 all repair from one shared truth.

WR-00 does **not** perform layout repair, visual redesign, support-art generation, or structural rollback. It exists so those later packets cannot reinterpret the failure state or claim cleanup legality early.

## B. Source hierarchy for World recovery

World recovery follows this authority order:

1. **Current semester gameplay truth** (live module/routing/travel/readiness semantics in runtime code).
2. **Locked World redesign truth** (preserve-first, additive, no destructive cleanup before gate pass).
3. **Intended World mockup/contact sheet** (target composition/atmosphere reference).
4. **Current repo as practical base** (existing WorldScreen/CityMapHub/inspector/dock implementation).
5. **Current failed World screenshot** (authoritative failure baseline for recovery sequencing).

## C. Preserve-first law for World

- No old scenic/background/header/icon removal until exact-screen cutover approval is granted.
- Shared shell component adoption does not grant cleanup authority by itself.
- No packet may leave World in a more dashboard-like, over-abstracted, or less map-owned state than preserve-first target composition.

## D. Current screenshot vs target mockup comparison

### overall ownership
- **Current failed screenshot baseline:** ownership appears fragmented across selector slab, map labels, inspector, and lower support deck.
- **Target mockup:** one dominant scenic owner with clearly subordinate support surfaces.

### map treatment
- **Current:** map reads as a boxed slab/container.
- **Target:** map reads as the page hero plane.

### label treatment
- **Current:** on-map labels behave as oversized mini-cards carrying role/guidance/output payload.
- **Target:** diegetic labels identify place/action without replacing inspector/card responsibilities.

### information zoning
- **Current:** selected/recommendation/shortcut teaching signals are distributed across too many equal-weight zones.
- **Target:** above-the-fold command truth is calmer, with fewer concurrent high-importance clusters.

### negative space
- **Current:** compressed, control-wall-like top and center regions with reduced scenic breathing room.
- **Target:** map-led negative space supports navigation legibility and atmosphere.

### inspector role
- **Current:** inspector carries selected explanation + summary + recommendation + shortcuts + teaching concurrently.
- **Target:** inspector is secondary, focused, and non-duplicative.

### lower navigation role
- **Current:** lower support deck risks reading as leftover tabs/cards and colliding with ritual dock ownership.
- **Target:** lower navigation ownership remains calm and singular.

### scenic breathing room
- **Current:** dashboard density reduces scenic authority.
- **Target:** scenic map remains primary visual anchor.

### recommendation/shortcut containment
- **Current:** urgency/support signals compete across multiple zones.
- **Target:** recommendation/shortcut truth is contained and readable without creating extra owners.

- **Preserve while fixing:** map art/overlays, current travel truth, bottom dock, module truth.
- **Primary owner packet:** **WR-01**.
